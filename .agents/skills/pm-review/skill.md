# 产品经理审查工作流

> **角色**: 产品经理（PM）
> **目标**: 先理解产品意图，再以用户视角审查功能实现，识别体验问题和功能缺失，给出优先级建议并实施修复。
> **适用场景**: 功能迁移完成后、版本发布前、用户反馈评估时。
>
> **核心理念**: PM 审查不是代码检查清单，而是产品思维。先问"为什么要有这个功能"，再问"怎样才算做好了"，最后才检查"实现是否达标"。
>
> **⚠️ 重要**: 当前 Flutter 页面是全新独立设计，与之前的 HTML 原型页面没有任何关系。审查时**严禁**参考、对比或查找任何 HTML 文件。

---

## ❗ 步骤执行纪律（强制执行）

| 规则 | 说明 |
|------|------|
| **步骤2 不可跳过** | 必须先回答"为什么/怎样算好/用户怎么想"三个问题，再进入后续步骤 |
| **步骤2.6 强制执行** | 必须填写 CRUD 矩阵、导航链路矩阵、交互功能矩阵、数据流矩阵，识别缺失功能 |
| **严禁合并步骤** | 步骤3（用户旅程）和步骤4（UI/UX审查）必须分开执行 |
| **步骤3.3 强制执行** | 必须 grep 可交互元素、逐条验证跳转链路、列出断裂链路 |
| **步骤4 必须调用 skill** | 必须显式调用 `ui-ux-pro-max` 技能并执行搜索命令 |
| **步骤4 必须执行响应式审查** | 步骤 4.6 强制逐组件检查 Mobile/Tablet/Desktop 三端布局 |
| **执行顺序** | 步骤1 → 2 → 3 → 4 → 5 → 6 → 7，严格顺序 |

## 核心原则

### PM 视角优先级

| 等级 | 定义 | 示例 |
|------|------|------|
| **P0 阻断** | 功能不可用 / 数据损坏 | 点击按钮无反应、文件上传乱码 |
| **P1 体验** | 可用但体验差 | 缺少引导、按钮位置不合理 |
| **P2 增强** | 功能可用但不完善 | 状态展示不全、缺少批量操作 |
| **P3 优化** | 技术债 / 代码质量 | 重复代码、命名不规范 |

### 响应式兼容要求（手机 + Web）

| 平台 | 屏幕宽度 | 交互模式 | 布局考量 |
|--------|----------|----------|----------|
| **手机** | < 600px | 触摸操作、底部弹窗 | 单列布局、触摸目标 ≥ 44x44 |
| **平板** | 600-1024px | 触摸 + 光标 | 可选双栏布局 |
| **Web/桌面** | > 1024px | 鼠标 + 键盘 | 双栏/多栏布局、hover状态、最大宽度约束 |

**关键规则**：
- 使用 `ResponsiveBuilder` (`core/layout/responsive_builder.dart`)
- Web 端：宽屏内容需 `maxWidth` 约束，弹窗可用 Dialog 替代 BottomSheet
- 手机端：触摸目标 ≥ 44x44px，SafeArea 正确包裹，长文本 `TextOverflow.ellipsis`

## 步骤 2：产品思维分析 —— ❗灵魂步骤，不可跳过

### 2.1 为什么要有这个功能？

| 问题 | 输出 |
|------|------|
| **目标用户是谁？** | 描述用户画像 |
| **用户的核心痛点是什么？** | 没有这个功能时用户怎么解决？ |
| **这个功能的业务价值是什么？** | 提升效率？降低成本？增加可控性？ |
| **功能在产品中的位置？** | 核心功能还是辅助功能？与哪些功能关联？ |

### 2.2 怎样才算做好了？

| 维度 | 输出 |
|------|------|
| **用户能完成的核心任务** | 列举 3-5 个核心任务 |
| **完成任务的步骤上限** | 每个任务理想需要几步？超过 3 步就要警觉 |
| **用户应该看到什么反馈** | 每个操作的预期结果 |

### 2.3 用户的心智模型是什么？

| 问题 | 输出 |
|------|------|
| **用户期望的信息架构** | 进入页面时最想先看到什么？ |
| **用户期望的操作流向** | 查看完信息后下一步最可能做什么？ |
| **用户的怡当行为** | 哪些场景下用户会犹豫或误操作？ |

### 2.4 竞品/行业对标（可选但推荐）

> 快速思考同类产品如何解决同样的问题，避免闭门造车。

| 问题 | 输出 |
|------|------|
| **同类产品有没有类似功能？** | 列举 1-2 个（如 Notion 日报、飞书日报、GitHub Insights） |
| **它们的交互模式是什么？** | 卡片式/时间线/仪表盘/邮件推送？ |
| **我们的差异化在哪？** | 有什么做得更好？有什么可以借鉴？ |
| **行业最佳实践** | 这类功能通常包含哪些子功能？我们是否遗漏？ |

> 此步骤不要求深度调研，基于已有知识快速对标即可。如果对该领域不熟悉可跳过。

### 2.5 产品思维小结

用一段话总结："这个功能让 [**目标用户**] 能够 [**完成什么任务**]，通过 [**什么方式**]，解决了 [**什么痛点**]。"

### 2.6 功能完整性矩阵 —— ❗链路闭环核心

> 基于 2.2 的核心任务，逐个检查**当前代码是否已实现**。不是检查代码质量，而是检查**功能是否存在**。

#### 2.6.1 CRUD 完整性检查

对该模块涉及的每个数据实体，填写：

| 数据实体 | Create | Read(列表) | Read(详情) | Update | Delete | 当前状态 |
|----------|--------|-----------|-----------|--------|--------|---------|
| 例：员工 | ✅ 有入口 | ✅ 列表页 | ✅ 详情页 | ❌ 无编辑入口 | ❌ 无删除 | 缺 U/D |

#### 2.6.2 导航链路闭环检查

检查所有页面间的**双向导航**是否完整：

```
入口在哪？→ 当前页面 → 能去哪？→ 能回来吗？
```

逐条检查：

| 链路 | 起点 | 终点 | 前进入口 | 返回方式 | 状态 |
|------|------|------|---------|---------|------|
| 例 | 首页简报卡片 | 简报详情页 | ✅ onTap | ✅ 返回按钮 | 完整 |
| 例 | 员工汇报卡片 | 员工详情页 | ❌ 无跳转 | — | **断裂** |

重点关注：
- **页面内的可交互元素**（卡片、按钮、链接）是否都有对应跳转目标？
- **详情页/子页面**是否有返回入口？
- **操作完成后**是否自动返回或刷新上级页面？
- **跨模块引用**是否可跳转（如简报页 → 员工详情页、警告按钮 → 目标页面）？

#### 2.6.3 交互功能完整性检查

| 交互能力 | 是否需要 | 是否已实现 | 备注 |
|----------|---------|-----------|------|
| 下拉刷新 | 如果有异步数据 | ✅/❌ | |
| 搜索/筛选 | 如果列表 > 10 项 | ✅/❌ | |
| 排序 | 如果有时间/优先级维度 | ✅/❌ | |
| 分页/懒加载 | 如果数据量大 | ✅/❌ | |
| 批量操作 | 如果需要多选处理 | ✅/❌ | |
| 操作确认弹窗 | 如果有不可逆操作 | ✅/❌ | |
| 成功/失败反馈 | 任何写操作 | ✅/❌ | |
| 加载态 | 异步请求时 | ✅/❌ | |
| 空状态引导 | 无数据时 | ✅/❌ | |
| 错误态+重试 | 请求失败时 | ✅/❌ | |

#### 2.6.4 数据流闭环检查

> 验证数据从 API 到 UI 的完整流转路径，确保每个环节无断裂。

对该模块的每个 API 接口，逐条检查：

| API 端点 | Repository 方法 | Provider 定义 | UI 绑定 | 错误处理 | 缓存/刷新 | 状态 |
|---------|----------------|--------------|--------|---------|----------|------|
| 例：POST /briefing/today | getTodayBriefing | briefingDataProvider | asyncData.when() | ✅ error 分支 | ✅ invalidate | 完整 |
| 例：DELETE /worker/:id | — | — | — | — | — | **未实现** |

重点关注：
- **写操作后数据一致性** — 创建/更新/删除后是否 `invalidate` 相关 Provider 刷新列表？
- **乐观更新 vs 等待响应** — 是否有合理的加载反馈？
- **错误回滚** — 操作失败后 UI 是否恢复到操作前状态？
- **Provider 生命周期** — `autoDispose` 是否合理？跨页面共享数据是否会被意外销毁？

## 步骤 3：绘制用户旅程地图

> 以用户视角走查每个核心任务，不是遍历代码路径。

### 3.1 核心场景（至少覆盖）

1. **首次使用** — 新用户能否立即理解这个页面是做什么的？
2. **核心操作** — CRUD 主流程是否顺畅直觉？
3. **数据上传/导入** — 如有上传功能
4. **搜索/筛选** — 如有搜索功能
5. **异常场景** — 网络错误、空数据、权限不足
6. **操作后反馈** — 每个操作是否有明确的成功/失败反馈？
7. **错误恢复** — 出错后能否重试？

### 3.2 旅程审查格式

```
场景：[xx]
用户目标：[xx]
操作路径：入口 → 步骤1 → 步骤2 → ... → 结果
是否顺畅：✅/❌ + 原因
是否符合用户心智模型：✅/❌ + 原因
发现的问题：[P等级] 问题描述 → 影响分析 → 建议修复
```

每个问题必须回答：严重等级、阻碍了哪个核心任务、用户的感受、修复后体验变化。

### 3.3 链路闭环走查 —— ❗必须执行

> 基于步骤 2.5 的导航链路矩阵，在代码层面逐条验证。

#### 3.3.1 页面内可交互元素逐一检查

grep 当前 feature 目录下所有 `onTap`、`onPressed`、`context.go`、`context.push` 调用，确认：

```bash
grep -rn "onTap\|onPressed\|context\.go\|context\.push\|context\.pop" flutter_client/lib/src/features/<feature>/presentation/
```

逐条验证：
- 每个 `onTap`/`onPressed` 都有实际逻辑（非空回调、非 `// TODO`）
- 每个跳转目标路由在 `app_routes.dart` 中已注册
- 每个跳转目标页面已实现（非 placeholder）

#### 3.3.2 缺失链路识别

基于 2.5 + 旅程走查，列出**用户期望能跳转但实际没有入口的链路**：

| 用户期望 | 当前页面元素 | 期望跳转目标 | 实际行为 | 严重等级 |
|---------|------------|------------|---------|---------|
| 例：点击员工卡片查看详情 | 员工汇报卡片 | 员工详情页 | 无 onTap | P1 |
| 例：点击协作记录查看参与者 | 协作记录项 | 协作详情页 | 无跳转 | P2 |

#### 3.3.3 关联模块入口检查

检查当前页面是否提供了**与之关联的其他模块的入口**。参考 `app_routes.dart` 中该 feature 相关的所有路由：

```bash
grep -i "<feature_keyword>" flutter_client/lib/src/core/navigation/app_routes.dart
```

对比：路由已定义但页面内无入口 → 标记为**链路断裂**。

## 步骤 4：UI/UX 专业审查（ui-ux-pro-max）—— ❗必须独立执行

> **此步骤不能与步骤3合并执行。**

### 4.1 加载 ui-ux-pro-max 技能

```
skill(SkillName: "ui-ux-pro-max")
```

### 4.2 获取 Flutter Stack 指南

```bash
python3 .Codex/skills/ui-ux-pro-max/scripts/search.py "<feature_keywords>" --stack flutter
```

### 4.3 获取 UX 最佳实践

```bash
python3 .Codex/skills/ui-ux-pro-max/scripts/search.py "loading empty state error feedback" --domain ux
python3 .Codex/skills/ui-ux-pro-max/scripts/search.py "animation accessibility touch target" --domain ux
```

### 4.4 审查清单

| 维度 | 检查项 | 方法 |
|------|--------|------|
| **触摸交互** | 最小点击区域 44x44 | 检查 `SizedBox` 约束 |
| **触摸交互** | 异步操作时禁用按钮 | 检查 `isUploading ? null : onTap` |
| **加载状态** | 使用骨架屏而非空白 | 检查 loading 分支 |
| **空状态** | 空数据有引导 UI + 操作按钮 | 检查 `.isEmpty` 分支 |
| **动画** | 过渡 150-300ms | 检查 `Duration` 参数 |
| **主题色** | 禁止硬编码颜色 | grep `Colors\.` |
| **响应式-Mobile** | 触摸目标、SafeArea、底部弹窗 | 检查 `SafeArea` 包裹 |
| **响应式-Web** | 内容最大宽度、hover状态 | 检查 `ConstrainedBox/maxWidth` |

### 4.5 将 UI 审查问题追加到步骤 3 问题清单，标注来源为 `[UX]`。

### 4.6 响应式布局专项审查 —— ❗强制执行

1. 确认项目使用的断点系统（`context.isDesktop` / `context.isTablet` / `context.isMobile`）
2. grep 检查当前 feature 目录下的布局分支情况
3. 逐组件填写三端适配矩阵：

| 组件 | Mobile 布局 | Tablet 布局 | Desktop 布局 | 问题 |
|------|-------------|-------------|-------------|------|
| xxx_page.dart | 单列 | ❓未处理 | 双列 | Tablet被当作 Mobile |

常见问题：只区分 `isDesktop` vs 非桌面导致 Tablet 被当 Mobile 处理；Web 宽屏无 maxWidth 约束；底部弹窗在 Web 上体验不佳。

### 4.7 性能审查（列表页/数据密集页重点检查）

| 检查项 | 方法 | 严重等级 |
|--------|------|---------|
| **列表虚拟化** | 长列表是否使用 `ListView.builder` / `SliverList` 而非 `Column(children: list.map)` | P1 |
| **图片懒加载** | 图片列表是否使用 `CachedNetworkImage` 或 `Image.network` 的 `loadingBuilder` | P2 |
| **Provider 重建范围** | `ref.watch` 是否在最小粒度 Widget 上调用，避免不必要的全页面重建 | P2 |
| **const 构造函数** | 静态 Widget 是否标记为 `const`，减少不必要的重建 | P3 |
| **分页加载** | 数据量大的列表是否实现分页/无限滚动，避免一次加载全量数据 | P1 |
| **debounce 搜索** | 搜索输入是否有防抖处理（≥ 300ms），避免频繁 API 调用 | P2 |

```bash
# 检查是否有低效的列表构建
grep -rn "Column\|Row" flutter_client/lib/src/features/<feature>/presentation/ | grep "\.map("
```

## 步骤 6：实施修复

### 6.1 创建 TODO 列表（按优先级排序）

### 6.2 修复顺序

P0 → P1 → P2 → P3，每项修复后编译验证：

```bash
cd flutter_client && dart analyze lib/src/features/<feature>/ 2>&1 | grep -E "error|warning" | head -20
```

### 6.3 代码修改原则

- **最小改动**: 只改必要的部分
- **保持风格**: 遵循现有代码风格和命名约定
- **共享优先**: 发现重复代码先抽取为共享组件
- **用户信息**: 必须用 `opcSpaceIdProvider`/`opcUserIdProvider`，禁止硬编码
- **编译通过**: 每次修改后必须通过 `dart analyze` 零 error

### 6.4 常见修复模式

| 问题类型 | 修复模式 |
|---------|---------|
| 空状态无引导 | 添加 `SliverFillRemaining` 空状态 Widget，含图标+文案+操作按钮 |
| 按钮过多挤占 Header | 收进 `PopupMenuButton` 更多菜单 |
| 搜索未实现 | 隐藏搜索栏 UI，删除未使用的 Widget |
| 操作无反馈 | 添加 `SnackBar` 成功/失败提示 |
| 状态不自动刷新 | 操作后 `ref.invalidate()` 对应 Provider |
| 功能入口缺失 | 在 Section Header 添加操作链接（如 "管理 →"） |
| 重复代码 | 抽取到 `presentation/widgets/` 共享组件 |
| 二进制文件编码 | 文本文件用 `utf8.decode`，二进制文件用 `base64Encode` |
| Web 宽屏内容拉伸 | 外层包裹 `Center` + `ConstrainedBox(maxWidth: 800)` |
| Web 上底部弹窗不合理 | Mobile 用 BottomSheet，Web 用 Dialog |
| 横向列表 Web 不支持滚轮 | 包裹 `Scrollbar` 或改为网格布局 |
| 硬编码颜色 | `Colors.red` → `colorScheme.error` |
| **链路断裂-卡片无跳转** | 给卡片 Widget 添加 `onTap` 回调 + `InkWell` 包裹 + `context.push(route)` |
| **链路断裂-缺少详情入口** | 在列表项添加 `>` 箭头图标 + `onTap` 跳转到详情页路由 |
| **链路断裂-跨模块无入口** | 在相关 UI 元素（如员工名称）上添加 `GestureDetector` + `context.push('/target')` |
| **链路断裂-操作按钮无目标** | 检查 `actionRoute` 路由是否已注册，未注册则先在 `app_routes.dart` 添加 |
| **链路断裂-返回路径缺失** | 页面顶部添加返回按钮 `context.canPop() ? context.pop() : context.go('/fallback')` |
| **CRUD 缺失-无创建入口** | 在列表页 Header/FAB 添加创建按钮 + 跳转创建页或弹窗 |
| **CRUD 缺失-无编辑入口** | 在详情页/卡片添加编辑按钮 + 跳转编辑页或弹窗 |
| **CRUD 缺失-无删除入口** | 在详情页/卡片长按/更多菜单中添加删除选项 + 确认弹窗 |
