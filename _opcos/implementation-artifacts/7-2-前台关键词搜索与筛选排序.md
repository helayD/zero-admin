# Story 7.2: 前台关键词搜索与筛选排序

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 消费者,
I want 通过关键字、分类、品牌和排序条件搜索商品,
So that 我可以更快找到想买的商品而不只依赖导购入口。

## Acceptance Criteria

1. **Given** 搜索索引中存在可售商品 **When** 消费者输入关键字并使用分类、品牌或排序条件 **Then** 系统返回匹配的商品列表 **And** 结果只包含当前作用域内可见且可售的商品。

2. **Given** 搜索无结果或索引延迟导致结果受限 **When** 消费者执行搜索 **Then** 页面展示明确的空状态或提示信息 **And** 不返回与真实商品状态不一致的过期结果。

## Dev Notes

### 架构约束与边界（继承自 Epic 7 + Architecture）

**约束 1：ES 是搜索读模型，前台搜索只读 ES**

- 搜索结果来自 `rpc/search` 的 ES 查询，不直连 PMS MySQL
- Story 7-1 已建立 PMS → MQ → Consumer → ES 同步链路
- 前台搜索延迟上限：5 分钟（NFR22）

**约束 2：Scope 隔离是强制性要求**

- 所有搜索结果必须经过 Scope 过滤
- `rpc/search/internal/logic/common/es_query.go:ScopeFilters` 已内置 scope 过滤
- front-api 必须正确传递 Scope 到 Search RPC

**约束 3：搜索服务降级要求**

- ES/Search RPC 不可用时，必须返回明确降级反馈
- 不允许静默失败（NFR21）
- 降级日志需包含 traceId

**约束 4：禁止绕过 Search RPC 直连 ES**

- front-api 只能通过 `rpc/search.Search` 方法查询
- 禁止在 front-api 或 Flutter 中直连 ES
- ES 索引名称、字段映射不得硬编码在 front-api

### 通信拓扑

```
# 前台搜索链路（Story 7-2 实现范围）
Flutter Mall → front-api → Search RPC: Search
  → ScopeFilters(platformId, tenantId, merchantId)
  → ES products 索引（带 scope 过滤，只返回 publish_status=1 的商品）
  → 返回匹配商品列表

# 前置依赖（Story 7-1 已实现）
PMS MySQL → PMS 写操作 → MQ 事件 → Consumer → ES products 索引
```
