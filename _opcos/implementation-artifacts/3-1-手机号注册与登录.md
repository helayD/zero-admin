# Story 3.1: 手机号注册与登录

## 状态: done

## Story

**As a** 消费者,
**I want** 使用手机号完成注册和登录,
**So that** 我可以在移动端进入自己的账户并开始购物。

## Epic 上下文

**Epic 3: 会员账户、地址与用户资产中心**
消费者可以完成注册登录、维护个人资料和地址，并查看积分、成长值、优惠券及相关会员资产；运营可以管理会员规则与权益。

**FRs implemented:** FR8

**本 Story 是 Epic 3 的首个 Story，需要为后续 Story（个人资料、地址管理、用户资产等）奠定认证基础。**

## 验收标准

### AC-1: 密码登录成功
**Given** 消费者输入已注册的手机号和正确密码
**When** 提交登录请求
**Then** 系统识别会员身份并返回 JWT 登录态（token + tokenHead）
**And** 登录会话绑定当前租户或商户入口上下文

### AC-2: 手机号注册成功
**Given** 消费者输入未注册的有效手机号、昵称和密码
**When** 提交注册请求
**Then** 系统创建会员记录并返回 JWT 登录态
**And** 新会员默认等级为 level_id=1，积分和成长值为 0

### AC-3: 登录失败 — 账号不存在
**Given** 消费者输入未注册的手机号
**When** 提交登录请求
**Then** 系统返回"账号不存在"的可理解错误
**And** 不泄露敏感安全信息或后台内部错误细节

### AC-4: 登录失败 — 密码错误
**Given** 消费者输入已注册手机号但密码不正确
**When** 提交登录请求
**Then** 系统返回"账号密码不对"的可理解错误

### AC-5: 注册失败 — 手机号已存在
**Given** 消费者输入已注册的手机号
**When** 提交注册请求
**Then** 系统返回"手机号已注册"
**And** 不创建重复会员记录

### AC-6: 注册失败 — 两次密码不一致
**Given** 消费者输入的密码和确认密码不一致
**When** 提交注册请求
**Then** front-api 层直接拦截返回"两次密码不一致"，不调用 RPC

### AC-7: 账号禁用拦截
**Given** 消费者的账号 is_enabled=0（被禁用）
**When** 提交登录请求
**Then** 系统返回明确的禁用提示，不返回 token

### AC-8: 首次登录优惠券发放
**Given** 会员 first_login_status=1（首次登录）
**When** 登录成功后
**Then** 系统通过 RabbitMQ 异步发送新手优惠券消息到 `coupon.event.exchange`
**And** 不阻塞登录主流程

### AC-9: 登录日志记录
**Given** 任何成功的登录请求
**When** 登录完成
**Then** 系统在 `ums_member_login_log` 中写入一条记录（IP、来源、时间）
**And** 日志写入失败不影响登录主流程

### AC-10: Flutter 移动端登录流程
**Given** 消费者在 Flutter 移动端打开登录页面
**When** 输入手机号和密码并点击登录
**Then** App 通过 `HttpUtil.post` 发送请求到 `/api/member/login`
**And** 成功后将 `Bearer <token>` 存入 SharedPreferences 并返回上一页

### AC-11: Flutter 401 自动跳转与意图恢复
**Given** 消费者的 token 过期或无效
**When** 任何请求返回 HTTP 401
**Then** App 自动跳转到登录页面
**And** 登录成功后自动恢复到触发 401 时的原始页面/路由，而不是回到首页

### AC-12: 密码强度校验
**Given** 消费者在注册或登录时输入密码
**When** 密码长度不足 6 位
**Then** 前端和后端同时拒绝请求并返回明确的密码长度提示

## 任务与子任务

### 任务 1: 后端 — 增强注册与登录安全性 [backend]

#### 1.1 密码哈希化 ✅
- **当前问题**: `ums_member_info.password` 存储明文密码，`loginlogic.go` 使用 `member.Password != in.Password` 明文比较
- **改造目标**:
  - 在 `registerlogic.go` 中注册时使用 `bcrypt` 或 `golang.org/x/crypto/bcrypt` 对密码进行哈希
  - 在 `loginlogic.go` 中登录时使用 `bcrypt.CompareHashAndPassword` 比较
  - **注意**: 需要兼容已有的明文密码测试数据（可在登录时检测：如果密码未哈希则先比明文，匹配后升级为哈希存储）
- **涉及文件**:
  - `rpc/ums/internal/logic/memberinfoservice/registerlogic.go`
  - `rpc/ums/internal/logic/memberinfoservice/loginlogic.go`

#### 1.2 账号状态校验 ✅
- **当前问题**: `loginlogic.go` 未校验 `is_enabled` 字段，禁用账号仍可登录
- **改造目标**: 登录时查询到会员后，增加 `is_enabled` 校验，禁用账号返回明确错误
- **涉及文件**: `rpc/ums/internal/logic/memberinfoservice/loginlogic.go`

#### 1.3 修复注册逻辑中的 member_id 生成方式 ✅
- **当前问题**: `registerlogic.go` 中 `insertMember` 使用 `query.UmsMemberInfo.Last()` 获取最后一条记录的 member_id+1，存在并发安全问题；且如果表为空会 panic
- **改造目标**: 使用 Redis `INCR ums:member_id_seq`（初始值设为当前最大 member_id）生成 member_id，保持与现有数据（1001-1005）的连续性
- **⚠️ 注意**: `member_id` 是业务标识（JWT claims 中的 `memberId`），与表主键 `id`（auto_increment）用途不同，**严禁混用**。修改 member_id 值域会导致所有已发放 JWT 失效
- **涉及文件**: `rpc/ums/internal/logic/memberinfoservice/registerlogic.go`

#### 1.4 手机号格式校验 ✅
- **当前问题**: 注册和登录均未校验手机号格式
- **改造目标**: 在 front-api 层（或 RPC 入口）增加中国大陆手机号正则校验 `^1[3-9]\d{9}$`
- **涉及文件**:
  - `api/front/internal/logic/member/member/register_logic.go`
  - `api/front/internal/logic/member/member/login_logic.go`

#### 1.5 密码长度校验 ✅
- **改造目标**: 前后端同步校验密码最短 6 位。front-api 层在调用 RPC 前拦截，Flutter 端在提交前校验
- **涉及文件**:
  - `api/front/internal/logic/member/member/register_logic.go`
  - `api/front/internal/logic/member/member/login_logic.go`
  - `flutter-mall/lib/view/mine/login/login.dart`

#### 1.6 登录日志 IP 地域字段 ✅
- **当前问题**: `loginlogic.go` 中登录日志的 `City` 和 `Province` 硬编码为 `"todo"`
- **改造目标**: 可暂时保留 todo，但记录真实 IP。后续 Story 可接入 IP 地域库
- **涉及文件**: `rpc/ums/internal/logic/memberinfoservice/loginlogic.go`
- **优先级**: 低 — 不阻塞本 story 验收
- **实际处理**: 保持 todo 原样，真实 IP 已通过 `in.Ip` 记录

### 任务 2: 后端 — JWT 库升级与 Token 安全 [backend]

#### 2.1 JWT 库升级 ✅
- **当前问题**: `createtoken.go` 使用已废弃的 `github.com/dgrijalva/jwt-go`
- **改造目标**: 迁移到 `github.com/golang-jwt/jwt/v5`（社区维护的后继版本）
- **涉及文件**: `rpc/ums/internal/logic/memberinfoservice/createtoken.go`
- **注意**: JWT 签名密钥 `ad879037-c7a4-4063-9236-6bfc35d54b7d` 在 `rpc/ums/etc/ums.yaml` 和 `api/front/etc/front-api.yaml` 中必须一致

### 任务 3: Flutter 移动端 — 登录页面增强 [frontend-mobile]

#### 3.1 登录错误处理与用户反馈 ✅
- **当前问题**: `login.dart` 的 `_submitLoginData` 没有 try-catch，登录失败时无任何用户提示；登录成功后直接 `Navigator.pop()` 无论是否成功
- **改造目标**:
  - 添加 try-catch，失败时显示 SnackBar 或 Dialog
  - 只在登录成功（`code == 0`）时保存 token 并 pop
  - 登录请求期间显示 loading 状态，防止重复提交
- **涉及文件**: `flutter-mall/lib/view/mine/login/login.dart`

#### 3.2 注册入口 ✅
- **当前问题**: Flutter 登录页面仅支持登录，无注册入口。页面已显示"未注册的手机号登录成功后将自动注册"提示，但后端 login 接口并不自动注册
- **改造目标**: 在登录页底部增加"还没有账号？立即注册"文本链接，跳转到独立注册页面
- **注册页面**: 新建 `register.dart`，包含手机号、昵称、密码、确认密码四个字段，调用 `POST /api/member/register`，复用 `LoginModel` 解析响应
- **涉及文件**:
  - `flutter-mall/lib/view/mine/login/login.dart`（添加注册入口链接）
  - 新建: `flutter-mall/lib/view/mine/login/register.dart`
  - `flutter-mall/lib/config/service_url.dart`（添加 `registerDataUrl`）

#### 3.3 输入校验 ✅
- **改造目标**: 在 Flutter 端增加手机号格式（`^1[3-9]\d{9}$`）和密码长度（≥6 位）的前端校验，校验失败时在对应输入框下方显示红色提示文字
- **涉及文件**: `flutter-mall/lib/view/mine/login/login.dart`、`register.dart`

#### 3.4 登录后意图恢复 ✅
- **当前问题**: `HttpUtil` 的 401 拦截器直接 `Navigator.push(Login())`，登录成功后 `Navigator.pop()` 回到上一页。但如果从深链/消息唤回触发登录，原始目标路由会丢失
- **改造目标**: 在 401 拦截时保存当前路由/目标意图，登录成功后尝试恢复到原始目标页而非简单 pop
- **UX 要求**: 来自 UX 设计 — "登录、升级、授权这些系统门槛必须让位于主任务，并在完成后回到原上下文"
- **涉及文件**:
  - `flutter-mall/lib/utils/http_util.dart`（401 拦截保存目标路由）
  - `flutter-mall/lib/view/mine/login/login.dart`（登录成功后恢复路由）

## 开发说明

### 架构约束

| 约束项 | 说明 |
|--------|------|
| **API 边界** | 移动端只访问 `front-api`（端口 9999），绝不直接打 RPC 服务 |
| **通信链路** | `flutter-mall -> front-api -> ums-rpc`（通过 gRPC） |
| **Handler 职责** | Handler 只负责参数解析和调用 Logic，不写业务逻辑 |
| **Logic 职责** | Logic 负责业务逻辑，调用 RPC client |
| **JWT 配置** | `AccessSecret` 必须在 `ums-rpc` 和 `front-api` 间保持一致 |
| **JWT 过期** | `AccessExpire: 86400`（24小时） |
| **Flutter 网络** | 必须使用 `HttpUtil`（基于 Dio），不绕过共享 HTTP 机制 |
| **Flutter 状态** | Token 存储使用 `SharedPreferencesUtil`，key 为 `token` |
| **生成代码** | `types.go`、`pb.go`、`gen/query/*` 为生成文件，**严禁手动修改** |
| **错误处理** | front-api 层使用 `errorx.NewDefaultError()` 包装 gRPC 状态码 |
| **错误响应一致性** | front-api 层所有业务失败统一走 `errorx.NewDefaultError()` 返回 HTTP 错误，**不要**在某些场景返回 `{code:1, message:"..."}` 而另一些场景返回 HTTP error。当前 `register_logic.go` 密码不一致时返回了 `{code:1}` 格式，需统一为 `errorx` 模式 |
| **密码安全** | 不在日志中打印明文密码，`logc.Errorf` 的参数需脱敏 |
| **异步消息** | 首次登录优惠券通过 RabbitMQ 发送，不阻塞登录主流程 |

### API 接口规范

**POST /api/member/register** （无需 JWT）
```json
// Request
{
  "nickname": "string",
  "password": "string",
  "confirmPassword": "string",
  "mobile": "string",
  "source": 1
}
// Response (成功)
{
  "code": 0,
  "message": "注册成功",
  "data": { "token": "jwt_string", "tokenHead": "Bearer" }
}
```

**POST /api/member/login** （无需 JWT）
```json
// Request
{
  "mobile": "string",
  "password": "string",
  "source": 1
}
// Response (成功)
{
  "code": 0,
  "message": "登录成功",
  "data": { "token": "jwt_string", "tokenHead": "Bearer" }
}
```

### RPC 接口（ums.proto 已定义）

- `MemberInfoService.Register(RegisterReq) -> RegisterResp`
- `MemberInfoService.Login(LoginReq) -> LoginResp`
- `MemberInfoService.UpdateFirstLoginStatus(UpdateFirstLoginStatusReq) -> UpdateMemberInfoResp`

## 关键风险与防护

| 风险 | 防护措施 |

## 依赖与前置条件

- **无外部依赖**：本 Story 是 Epic 3 的首个 Story，不依赖其他未完成 Story
- **Epic 1-2 前置**：平台基础设施（Epic 1）和商品导购（Epic 2）的 Story 已完成或不阻塞
- **中间件依赖**：RabbitMQ（首次登录优惠券消息）— 已在线上部署
- **Go 依赖新增**：`golang.org/x/crypto`（bcrypt）、`github.com/golang-jwt/jwt/v5`
  - 在 `rpc/ums/` 目录下执行 `go get golang.org/x/crypto` 和 `go get github.com/golang-jwt/jwt/v5`
  - 移除旧依赖：`go get -u` 后确认 `go.mod` 中不再需要 `github.com/dgrijalva/jwt-go`；若其他包间接依赖则保留但 createtoken.go 必须只 import 新库

### 后续 Story 前向约束

本 Story 建立的认证机制是 Epic 3 后续所有 Story 的基础：
- **Story 3.2（个人资料）**: 依赖 `GET /api/member/info` 的 JWT Auth，JWT claims 中的 `memberId` 用于查询个人信息
- **Story 3.3（收货地址）**: 依赖相同的 JWT Auth 和 `memberId`
- **Story 3.4（用户资产）**: 依赖 `memberId` 查询积分、优惠券等
- **约束**: JWT claims 结构（`memberId`、`memberName`、`mobile`）一旦发布不可随意变更字段名或值域，否则影响所有已登录用户

2. loginlogic.go: bcrypt 密码比较（兼容明文自动升级）+ is_enabled 校验 + 日志脱敏
3. createtoken.go: dgrijalva/jwt-go → golang-jwt/jwt/v5
4. register_logic.go / login_logic.go (front-api): 手机号正则 + 密码长度 + 统一 errorx 错误格式
5. login.dart: try-catch + loading + 输入校验 + SnackBar 反馈 + 注册入口 + redirectRoute 支持
6. register.dart: 新建注册页面（手机号/昵称/密码/确认密码，含校验和错误处理）
7. http_util.dart: 401 拦截器传递 redirectRoute 到 Login
8. service_url.dart: 添加 registerDataUrl
9. 单元测试: validation_test.go + password_test.go
