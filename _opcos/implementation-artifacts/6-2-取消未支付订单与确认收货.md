# Story 6.2: 取消未支付订单与确认收货

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 消费者,
I want 取消未支付订单并在收货后确认收货,
So that 我可以主动结束不再继续的订单或完成已收到商品的交易闭环。

## Acceptance Criteria

1. **Given** 订单处于待支付状态 **When** 消费者执行取消订单 **Then** 系统关闭该订单并更新用户侧状态 **And** 相关库存、优惠券和积分的后续处理进入可追踪链路。

2. **Given** 订单处于待收货状态 **When** 消费者确认收货 **Then** 系统更新订单完成状态 **And** 订单时间线与用户侧可执行动作同步更新为已完成语义。

## Dev Notes

### 架构约束与边界（继承自 Story 6-1 + Epic 5）

**约束 1：OMS 订单状态模型（已由 Story 6-1 确定）**

| OMS Status | 含义 | 对应操作按钮 |
|------------|------|-------------|
| 0 | 待支付 | 取消订单 + 立即付款 |
| 1 | 已支付/待发货 | 查看物流 |
| 2 | 已发货 | 查看物流 + 确认收货 |
| 3 | 已完成 | 申请售后 |
| 5 | 已取消 | 无操作按钮 |
| 7 | 售后中 | 申请售后 |

→ **取消订单**：仅 `orderStatus == 0` 时展示
→ **确认收货**：仅 `orderStatus == 2` 时展示
→ **已取消/已完成**订单不展示任何操作按钮

**约束 2：后端 Logic 现状**

- `cancel_user_order_logic.go`：完整实现（归属校验 + OMS CancelOrder + 库存释放 + 优惠券返还 + 积分返还）
- `confirm_receive_order_logic.go`：完整实现（归属校验 + OMS ConfirmOrder）
- **唯一缺失**：routes.go 中未注册两个路由
- 幂等保护：取消操作依赖 OMS `CancelOrder` 内部幂等，确认收货依赖 OMS `ConfirmOrder` 内部幂等

### 正确通信拓扑

```
取消订单：
flutter-mall → front-api（GET /api/order/cancelUserOrder?orderId=xxx）
  → CancelUserOrderHandler → CancelUserOrderLogic: memberId归属校验 → OMS CancelOrder
  → 释放锁库库存 → 返还优惠券 → 返还积分
  → 返回 CancelUserOrderResp{Code:0, Message:"取消订单成功"}

确认收货：
flutter-mall → front-api（GET /api/order/confirmReceiveOrder?orderId=xxx）
  → ConfirmReceiveOrderHandler → ConfirmReceiveOrderLogic: memberId归属校验 → OMS ConfirmOrder
  → 返回 ConfirmReceiveOrderResp{Code:0, Message:"操作成功"}
```
