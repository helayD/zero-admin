# Story 6.7: 商户订单与售后处理工作台

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 商户管理员,
I want 在商户作用域内处理本店订单与售后请求,
So that 我可以不依赖平台人工转单就完成日常履约与售后响应。

## Acceptance Criteria

1. **Given** 商户管理员进入订单与售后工作台 **When** 按订单状态、售后状态和时间筛选本店数据 **Then** 系统只返回当前商户作用域内的订单与售后请求 **And** 商户可以查看处理进度、补充备注并执行被授权的履约动作。

2. **Given** 商户管理员尝试访问其他商户订单或执行超出授权范围的售后操作 **When** 发起查询或处理请求 **Then** 系统拒绝操作并提示权限不足 **And** 所有商户侧处理结果保留审计记录供平台追溯。

3. **Given** 商户管理员需要确认已发给买家的货物 **When** 在工作台中对已支付订单执行发货确认 **Then** 系统更新订单发货状态并记录操作日志。

4. **Given** 买家提交了退货申请 **When** 商户管理员在工作台中审核退货请求 **Then** 系统更新退货状态并保留审核记录和原因。

> **⚠️ Story 6-7 与 Story 6-6 的核心区别**：

#### Task 1: 新建 `api/admin/doc/api/oms/merchant_workstation.api`

> **⚠️ admin-api 当前仅有面向平台/客服的订单 API**；Story 6-7 需要扩展商户自服务两类能力：
> 1. **商户工作台订单列表**：`queryMerchantOrderList` — 自动以当前 JWT MerchantId 为准，无需前端传 MerchantId
> 2. **商户订单发货确认**：`confirmMerchantDelivery` — 商户确认发货，更新物流信息

```
@server(
    jwt: AdminAuth
    middleware: Authority,Scope
)
service admin-api {
    @doc "商户工作台订单列表（自动以当前 JWT MerchantId 过滤，无需前端传参）"
    @handler queryMerchantOrderList
    post /api/oms/merchantOrder/list returns (MerchantOrderListResp)

    @doc "商户发货确认（复用已有 DeliveryReq，直接调用 OrderService.Delivery RPC）"
    @handler confirmMerchantDelivery
    post /api/oms/merchantDelivery/confirm returns (BaseResp)
}
```

## Dev Notes

### 架构约束与边界（继承自 Epic 6 + Story 6-1~6-6 实施成果）

**约束 1：Scope 过滤原则（核心区别于 Story 6-6）**

- 商户工作台数据 **仅按 `MerchantId` 过滤**，`TenantId` 从 JWT 获取但不出现在查询条件中
- `MerchantId` 从 JWT claims 提取，**不得由前端传递**，防止前端伪造商户 ID
- `admin-api` middleware 的 `Scope` 中间件负责校验权限
- 商户管理员**无法切换作用域**，始终只看本店数据（无需 GovernanceScopeBar）

**约束 2：OMS 真实状态值（与 Story 6-6 完全一致）**

OMS `order_status`（`rpc/oms/proto/order_main.proto`）：
```
1 = 待支付    (PendingPayment)
2 = 已支付/待发货  (Paid - AwaitingShipment)
3 = 已发货    (Shipped)
```

### Architecture Compliance

- **通信拓扑**：`web-admin(merchant) → admin-api → OMS RPC`；遵循 REST + gRPC 分层
- **Scope 优先**：所有 OMS 查询必须以 JWT MerchantId 为准，**前端不传 MerchantId**
- **幂等保护**：发货确认和退货处理接口防止重复提交
- **日志留痕**：所有商户操作写入 `order_operation_log`（`operator_type=3`）
- **商户自主**：商户管理员无需切换作用域，始终操作本店数据
- **Consequence Preview**：发货确认前展示业务影响说明
- **Recovery-first Feedback**：操作失败返回明确原因和修复入口
