# Story 2.4: 首页、分类与品牌导购浏览

Status: in-progress

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 消费者,
I want 从首页、分类和品牌页浏览商品,
so that 我可以快速发现符合兴趣和条件的可售商品。

## Acceptance Criteria

1. **Given** 首页、分类页或品牌页存在已发布商品  
   **When** 消费者进入对应导购页面  
   **Then** 系统按当前作用域返回广告位、推荐内容、分类商品或品牌商品列表  
   **And** 页面展示的商品状态、价格与库存提示与真实数据一致。
2. **Given** 当前分类、品牌或导购入口暂无可展示商品  
   **When** 消费者进入页面  
   **Then** 系统展示明确的空状态与下一步推荐入口  
   **And** 不使用长期静态占位数据误导用户。

## Dev Notes

### Scope Guardrails

- 本 story 负责"消费者从首页、分类和品牌页浏览商品"的完整导购体验闭环，是 Epic 2 从"商品可见性控制"（2.3）推进到"消费者实际看到可信商品列表"的关键步骤；不直接承担 2.5 商品详情聚合、2.6 专题/优选专区编排和 4.x 营销活动配置。[Source: `_opcos/planning-artifacts/1-new-feature/epic.md#Epic-2`; `_opcos/planning-artifacts/1-new-feature/epic.md#Story-24`]
- 本 story 必须建立在 2.3 已完成的前台可见性判定、作用域过滤和结构化失效反馈基础之上，不能绕开或弱化 2.3 的商品曝光规则。[Source: `_opcos/implementation-artifacts/2-3-商品上架审核与作用域可见性控制.md`]
- 本 story 不负责推荐算法、个性化排序、搜索功能（7.2）和秒杀活动配置（4.3）；首页秒杀模块保持现有实现，仅确保空数据时正确隐藏。[Source: `_opcos/planning-artifacts/1-new-feature/epic.md#Story-43`; `_opcos/planning-artifacts/1-new-feature/epic.md#Story-72`]

### Story Foundation / Business Context

- Epic 2 的目标是让商户和运营在正确作用域内发布商品与导购内容，让消费者通过首页、分类、品牌、专题与详情页发现可信、可售的商品。2.4 的核心任务是把 2.3 已建立的"可见商品池"以正确、一致且体验友好的方式呈现给消费者。[Source: `_opcos/planning-artifacts/1-new-feature/epic.md#Epic-2`]
- PRD FR1 要求消费者可以浏览首页导购内容，包括广告位、推荐品牌、新品、人气推荐和专题内容。FR2 要求消费者可以按照商品分类与品牌浏览商品集合。本 story 是 FR1 + FR2 的完整落地。[Source: `_opcos/planning-artifacts/1-new-feature/prd.md#商品发现与内容导购`]
- UX 设计强调"先显示作用域，再允许操作""状态必须可见、可解释、可恢复"。导购页面必须确保消费者看到的商品状态、价格与库存是真实可信的，空状态必须提供明确下一步而非静默空白。[Source: `_opcos/planning-artifacts/1-new-feature/ux-design.md#Experience-Principles`; `_opcos/planning-artifacts/1-new-feature/ux-design.md#Empty-States`]

### Technical Requirements

- 所有导购查询必须复用 2.3 建立的 `EnsureFrontProductVisible` 和 `ResolveEffectiveGovernanceScope` 作用域链路，不能为了"首页快"绕开统一规则。[Source: `_opcos/implementation-artifacts/2-3-商品上架审核与作用域可见性控制.md`; `api/front/internal/logic/common/product_visibility.go`; `api/front/internal/logic/common/governance.go`]
- 前台返回的商品 `price` 必须来自 SPU 的 `priceRange` 真实计算，不使用缓存或硬编码默认值。金额字段后端使用整数最小货币单位。[Source: `_opcos/planning-artifacts/1-new-feature/architecture.md#Format-Patterns`]
- 空状态处理遵循 UX 规范：移动端关键页面必须完整覆盖加载态、空态、错误态；空态提供明确下一步推荐入口。[Source: `_opcos/planning-artifacts/1-new-feature/ux-design.md#Empty-States`; `_opcos/planning-artifacts/1-new-feature/ux-design.md#Commerce-State-Shell`]
- 新增或修改 `.api` 源文件后必须通过 `goctl api go` 重新生成，不手改 `types.go`、`routes.go` 等生成物。[Source: `_opcos/project-context.md`]

### Flutter Mall / UX Requirements

- 首页导购页面结构遵循 UX 规范的"底部主导航 + 页面内分段入口"模式，各模块按"广告 → 快捷入口 → 品牌 → 秒杀 → 新品 → 人气 → 猜你喜欢"的既有顺序展示。[Source: `_opcos/planning-artifacts/1-new-feature/ux-design.md#Navigation-Patterns`]

- 所有图片加载使用既有 `CachedImageWidget`，不引入新的图片加载方案。[Source: `flutter-mall/lib/widgets/cached_image_widget.dart`]
