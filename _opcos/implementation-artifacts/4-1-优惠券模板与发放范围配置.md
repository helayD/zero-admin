# Story 4.1: 优惠券模板与发放范围配置

Status: done

## Story

As a 运营人员,
I want 创建优惠券模板并设置可见范围、领取规则和使用条件,
So that 我可以按平台、租户或商户经营策略发放可控的优惠权益。

## Acceptance Criteria

1. **Given** 运营人员进入优惠券管理后台 **When** 配置优惠券面额、门槛、有效期、适用商品范围和主体范围 **Then** 系统保存优惠券模板与作用域规则 **And** 模板状态支持草稿、已发布、已停用等明确语义。

2. **Given** 优惠券配置存在时间冲突、范围非法或主体越权 **When** 运营尝试发布模板 **Then** 系统阻止发布并指出具体冲突原因 **And** 不允许生成错误的发券规则。

### 状态语义映射（Story 4.1 核心改进点）

当前代码中 `status` 字段实际语义与 PRD 期望的"草稿→已发布→已停用"模型存在映射差异：

| 数据库值 | 当前语义 | 本轮 Story 映射 | 前端展示 |
|---------|---------|----------------|---------|
| 0 | 未开始 | 草稿/待发布 | 蓝色标签"草稿" |
| 1 | 进行中 | 已发布且在有效期内 | 绿色标签"进行中" |
| 2 | 已结束 | 过期或手动结束 | 灰色标签"已结束" |
| 3 | 已取消 | 运营主动取消 | 红色标签"已取消" |

**发布动作 = status 从 0 变更为 1**，同时需要做发布校验。现有 `UpdateCouponStatusLogic` 可复用为发布入口。

### Architecture Compliance

- **作用域模型**：已遵循平台/租户/商户三级隔离，`sms_coupon` 表带 `platform_id`/`tenant_id`/`merchant_id`
- **生成代码约束**：所有 model 通过 `gorm/gen` 生成，不可手改
- **通信拓扑**：`web-admin → admin-api → sms-rpc`，严格遵循 REST + gRPC 分层
- **Logic 层编排**：业务校验在 `logic` 层，handler 只做参数解析和响应
- **错误处理**：使用 `logc.Errorf` 记录内部错误，返回用户可理解错误信息
- **前端页面模式**：`index.tsx + service.ts + data.d.ts + components/*`
