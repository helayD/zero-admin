# Story 5.2: 购物车编辑、删除与批量结算

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 消费者,
I want 在购物车里修改数量、删除商品并选择批量结算,
So that 我可以在进入下单前整理出真正想购买的商品。

## Acceptance Criteria

1. **Given** 购物车中已有多个商品项 **When** 消费者修改数量、切换选中状态、删除单项或清空购物车 **Then** 系统即时更新购物车结果 **And** 显示对应促销信息、优惠金额和可售库存提示。

2. **Given** 购物车中存在失效、下架或不可售商品 **When** 消费者尝试批量结算 **Then** 系统高亮不可结算项并说明原因 **And** 仅允许有效商品进入下一步。

### 后端 API 层（front-api）— 编排校验层

> **⚠️ 关键架构约束（来自 Story 5-1 Dev Notes）**：oms-rpc 是纯数据服务，内部不做跨服务 RPC 调用。所有"编辑前商品可售状态校验"必须在 front-api 的 logic 层编排。

- [x] Task 1: front-api 编辑操作编排校验逻辑 (AC: #1, #2)
  - [x] 1.1 **修改数量**（`updateCartItemQuantity`）：
    - 调用 `UpdateCartItemQuantity` 时，**先**调用 PMS `ProductSkuService.QueryProductSkuDetail` 查询 SKU 库存
    - 若修改后数量 > 库存，返回具体错误码 `OMS_CART_STOCK_INSUFFICIENT`
    - 若商品已下架或审核不通过，返回 `OMS_CART_PRODUCT_OFFLINE` 或 `OMS_CART_PRODUCT_UNVERIFIED`
    - 数量合法时透传给 oms-rpc `UpdateCartItemQuantity`
  - [x] 1.2 **删除单项**（`deleteCartItem`）：
    - 删除操作本身不依赖商品状态，oms-rpc `DeleteCartItem` 直接标记 `delete_status=1`
    - 但删除成功后需触发购物车促销信息刷新（前端重新拉取 `queryPromotionList`）
  - [x] 1.3 **清空购物车**（`clearCartItem`）：
    - 调用 oms-rpc `DeleteCartItem`，ids 传空（oms-rpc 已有逻辑：ids 为空时删除当前会员所有有效购物车项）
    - 清空成功后前端清空 CartModel 数据
  - [x] 1.4 **批量结算前商品有效性校验**（AC: #2）：
    - 前端点击"去结算"时，**先**调用 front-api 新增 `POST /validateCartItems` 批量校验接口

    - 返回每项的校验结果 `{id, valid, errorCode, errorMessage}`
    - 前端根据返回高亮无效项，只放行全有效商品进入 OrderSubmit

## Dev Notes

### 架构约束与边界（继承自 Story 5-1）

**约束 1：oms-rpc 是纯数据服务，不做跨服务 RPC 调用**

`rpc/oms/internal/svc/service_context.go` 只注入了 `gorm.DB` 和 `RabbitMQ`，无 ProductService 客户端。

→ 因此："编辑前校验商品可售状态"必须在 front-api 层编排。PMS 状态查询 → 校验 → oms-rpc 写入的顺序与 Story 5-1 保持一致。

**约束 2：front-api JWT 不携带 scope**

`rpc/ums/internal/logic/memberinfoservice/createtoken.go` 创建的 JWT claims 只有 `memberId/memberName/mobile`，无 platform_id/tenant_id/merchant_id。

→ 因此：编辑/删除操作的 scope 校验**无法依赖 JWT scope**，商户级别隔离在 Epic 5 结算链路统一处理。

**约束 3：Flutter 购物车页面现状**

当前 `cart.dart` 存在以下功能缺口（**必须在 Story 5-2 补齐**）：
- ❌ 删除图标无绑定事件
- ❌ 无数量增减 UI
- ❌ 无清空购物车入口
- ❌ 无失效商品高亮
- ❌ 批量结算前无商品有效性校验

### 正确通信拓扑

```
编辑/删除操作：
flutter-mall → front-api → oms-rpc → MySQL
              ↑____________纯数据写入，不做跨服务调用_______________↑

数量修改校验：
flutter-mall → front-api → PMS（库存校验）→ front-api → oms-rpc（数量更新）

批量结算校验：
flutter-mall → front-api → [PMS 并行批量校验商品状态] → 返回校验结果 → flutter-mall
```

### Architecture Compliance

- **通信拓扑**：`flutter-mall → front-api → [PMS 状态校验（仅数量修改和批量结算）] → oms-rpc → MySQL`；遵循 REST + gRPC + DB 分层
- **Logic 层编排**：front-api 层负责跨域编排和状态校验；oms-rpc 层只做数据存取
- **错误处理**：front-api 使用 `errorx.NewDefaultError(s.Message())` 封装 gRPC 错误，Flutter 层复用 Story 5-1 错误码映射表
- **Flutter 网络层**：使用 `HttpUtil.get/post` 统一调用，**禁止** Widget 创建裸 `Dio`
- **Scope 模式**：遵循 Story 5-1 已知约束，scope 在 Epic 5 结算链路统一处理
