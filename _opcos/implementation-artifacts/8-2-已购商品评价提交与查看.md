# Story 8.2: 已购商品评价提交与查看

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 消费者,
I want 对已完成订单中的商品提交并查看评价,
so that 我可以沉淀消费反馈并为后续购买提供参考。

## Acceptance Criteria

1. [AC-1] Given 订单已完成且商品满足评价条件
   When 消费者提交评价内容、评分和补充信息
   Then 系统创建评价记录并关联对应订单与商品
   And 评价状态可在订单上下文中追溯。

2. [AC-2] Given 消费者查看商品评价内容
   When 商品详情页加载评价模块
   Then 系统展示已审核可见的评价信息（评分、内容、图片、时间、回复）
   And 不显示不属于当前商品或当前作用域的评价记录。

3. [AC-3] Given 已购消费者提交评价
   When 评价内容、评分、图片和订单关联信息传入
   Then 系统校验订单归属（memberId + orderId + productId）和评价条件
   And 返回明确的提交结果与评价状态。

4. [AC-4] Given 商品详情页加载评价模块
   When 前台请求评价列表
   Then 返回分页评价数据（评分、内容、图片、时间、回复）
   And 仅展示当前商品且已审核通过的评价。

5. [AC-5] Given 运营人员审核评价
   When 管理员执行通过、屏蔽或恢复动作
   Then 系统更新评价状态并记录处理人
   And 前台评价列表实时反映审核结果。

6. [AC-6] Given 运营人员查看评价详情
   When 进入评价详情页
   Then 展示评价原文、关联订单、商品信息、处理历史、回复列表
   And 支持按商品、状态、时间范围筛选。

## Dev Agent Guardrails（防止灾难性错误的强制约束）

### 🔴 强制约束：评价 MongoDB 无 scope 历史，必须新增

**警告：ProductComment MongoDB 模型** 当前**没有任何**治理范围字段！

经过 `rpc/pms/internal/logic/commentservice/` 深度分析：
- `AddCommentLogic`、`QueryCommentListLogic`、`UpdateCommentLogic` **均无** `platformId/tenantId/merchantId` 字段处理
- `ProductComment` 结构体 (`product_comment_types.go`) **没有** scope 字段定义
- MongoDB 查询仅按 `productId` 过滤，无 scope 条件

**必须修复（Task 0）：**
- `ProductComment` 新增 `platformId`、`tenantId`、`merchantId`、`memberId`、`orderId` 字段
- `AddCommentLogic.AddComment()` 保存所有 scope 字段
