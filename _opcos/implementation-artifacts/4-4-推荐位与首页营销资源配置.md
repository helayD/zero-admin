# Story 4.4: 推荐位与首页营销资源配置

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 运营人员,
I want 配置推荐位活动和首页营销资源,
So that 我可以把优惠权益和导购内容稳定投放到正确的商城入口。

## Acceptance Criteria

1. **Given** 运营人员拥有首页资源配置权限 **When** 创建或编辑推荐位活动和首页营销资源 **Then** 系统保存展示位置、适用内容、排序与作用域 **And** 配置结果可以按目标入口区分查看。

2. **Given** 推荐位资源缺少关键字段、超出生效时间或作用域冲突 **When** 运营尝试发布 **Then** 系统阻止发布并给出可理解的校验提示 **And** 不会把失效资源继续投放到前台入口。

### 后端 RPC 层（sms-rpc）— 首页推荐位无独立 RPC

**关键发现：首页推荐品牌、人气推荐商品、新品推荐、推荐专题这四个推荐位模块并不走 sms-rpc 独立 service，而是通过修改 PMS/CMS 中实体本身的状态标记来实现。**

- 品牌推荐 → `pmsclient.UpdateBrandRecommendStatus`（修改 `pms_product_brand.recommend_status`）
- 人气推荐商品 → `pmsclient.UpdateRecommendStatus`（修改 `pms_product_spu.recommend_status`）
- 新品推荐 → `pmsclient.UpdateNewStatus`（修改 `pms_product_spu.new_status`）
- 推荐专题 → `cmsclient.UpdateSubjectRecommendStatus`（修改 `cms_subject.recommend_status`）

因此本 story 在推荐位部分的后端改动主要集中在 admin-api 层和前端。

### Architecture Compliance

- **通信拓扑**：`web-admin → admin-api → sms-rpc`（广告）；`web-admin → admin-api → pms-rpc/cms-rpc`（推荐位）；`flutter-mall → front-api → sms-rpc + pms-rpc + cms-rpc`（首页聚合）
- **Logic 层编排**：所有校验逻辑在 sms-rpc `logic` 层或 admin-api `logic` 层，handler 只做参数解析和响应
- **错误处理**：sms-rpc 使用 `logc.Errorf` 记录内部错误 + `errors.New` 返回用户可理解信息；admin-api 使用 `errorx.NewDefaultError(s.Message())` 封装 gRPC 错误
- **前端页面模式**：`index.tsx + service.ts + data.d.ts + components/*`
- **作用域模型**：广告表缺少作用域字段（降级后续），推荐位通过 PMS/CMS 已有的作用域过滤实现
- **生成代码约束**：所有 model 通过 `gorm/gen` 生成（`query.SmsHomeAdvertise`），不可手改
