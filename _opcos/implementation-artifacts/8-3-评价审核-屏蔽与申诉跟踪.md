# Story 8.3: 评价审核、屏蔽与申诉跟踪

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 运营人员,
I want 审核、屏蔽和跟踪评价申诉状态,
So that 我可以在保证用户反馈价值的同时控制内容风险。

## Acceptance Criteria

1. **Given** 运营人员进入评价治理后台 **When** 审核、屏蔽、恢复或处理申诉 **Then** 系统更新评价状态并记录处理结果 **And** 前台仅展示当前审核通过的评价内容。

2. **Given** 评价存在争议或用户发起申诉 **When** 运营查看评价详情 **Then** 系统展示评价原文、处理历史和申诉状态 **And** 全过程保留可追踪记录。

## 背景与约束（必须优先阅读）

> **⚠️ CRITICAL - 数据存储差异：** `pms_product_comment` 使用 **MongoDB** 存储（不是 MySQL）！相关 Model 位于 `rpc/pms/gen/model/product_comment_model.go`，基于 `mon.Model` 实现。
>
> **⚠️ CRITICAL - Proto 文件路径：** `rpc/pms/proto/product_comment.proto` 已标注废弃，所有评价相关 proto 定义已迁移到 `rpc/pms/pms.proto`（第 845-859 行 `CommentService`）。
>
> **⚠️ CRITICAL - 字段冲突：** `showStatus` 字段已存在（0=屏蔽, 1=通过），本 Story 引入 `auditStatus` 作为更细粒度的 4 态审核状态，与 `showStatus` 并存但语义不同。
>
> **⚠️ CRITICAL - ID 类型：** MongoDB 的 `_id` 为 `bson.ObjectID`（string 类型），所有 RPC 请求/响应中的 `id` 字段类型为 `string`。

## Dev Notes

### 架构约束（必须遵守）

1. **数据存储差异：** 评价核心数据（`ProductComment`）使用 **MongoDB**，审核日志（`pms_comment_audit_log`）使用 **MySQL**。两者不得混淆。
2. **Proto 路径：** 所有评价相关 proto 定义在 `rpc/pms/pms.proto` 中，`proto/product_comment.proto` 已废弃。
3. **ID 类型：** MongoDB ObjectID 为 `string` 类型，所有 RPC 请求/响应的 `id` 字段为 `string`。
4. **字段语义区分：**
   - `showStatus`（已有）：前台可见性（0=屏蔽, 1=通过），Story 8-2 已实现
   - `auditStatus`（新增）：后台审核状态（0=待审核, 1=审核通过, 2=审核拒绝, 3=已屏蔽）
   - `hidden`（新增）：屏蔽标记（0=显示, 1=屏蔽），独立于 `auditStatus`
5. **作用域治理：** 所有写操作必须校验 `platform_id / tenant_id / merchant_id`，禁止跨主体修改。
6. **生成代码约束：** 字段变更必须修改 `.proto` 后 `make gen`，禁止手改 `.pb.go`。
