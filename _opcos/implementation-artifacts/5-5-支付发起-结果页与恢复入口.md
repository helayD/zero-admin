# Story 5.5: 支付发起、结果页与恢复入口

Status: backlog

## Story

As a 消费者,
I want 发起支付并在支付中断时快速恢复,
So that 我可以把首单交易顺利完成而不会因为状态不明而放弃。

## Acceptance Criteria

1. **Given** 订单已成功创建且处于待支付状态 **When** 消费者选择支付方式并发起支付 **Then** 系统生成支付请求并返回当前支付结果页或待支付恢复入口 **And** 用户无需等待未来订单模块也能确认当前支付状态。

2. **Given** 支付中断、失败或结果未及时返回 **When** 消费者回到支付结果页或待支付恢复入口 **Then** 系统展示剩余支付时间、失败原因和继续支付动作 **And** 用户可以继续支付或返回结算完成页而不丢失上下文。

## Dev Notes

### 架构约束与边界（继承自 Story 5-4）

**约束 1：`OrderPayLogic` 已激活支付宝 SDK 调用**

当前 `TradeAppPay` 已正确集成 `smartwalle/alipay/v3`：
- `PaymentOperationsUtils.TradeAppPay(outTradeNo, totalAmount, subject)` 返回支付宝 SDK 可用的 `orderInfo` 字符串
- 微信支付（`PayType=2`）目前无 SDK 调用，返回 mock 数据

→ Story 5-5 只需修复金额和标题的硬编码，以及补齐 `OrderPayQueryLogic`。

**约束 2：订单金额类型（proto 层 float32 → 前端 int64）**

OMS proto `OrderMain.pay_amount` 是 `float32`（元），后端 `OrderPayLogic` 传入 `TradeAppPay` 的 `totalAmount` 也是 `float32`。Flutter 显示时需做 `/100` 或 `/100.0` 转换。

→ Dev agent 需在 `OrderPay` 中对 `amount` 参数做单位说明注释（`amount` 单位：元，double）。

**约束 3：`OrderPayQueryResp.Data` 类型**

当前 `types/types.go` 中 `OrderPayQueryResp.Data` 为 `string`，返回给前端时需扩展为结构体。

→ Dev agent 需在 `types.go` 中新增 `OrderPayStatusData` 类型，并修改 `OrderPayQueryResp.Data` 为该类型。

### 正确通信拓扑

```
支付发起：
flutter-mall → front-api /orderPay（orderId, remark）
  → OMS/QueryOrderDetail（获取订单金额和商品）
  → AlipaySDK/TradeAppPay（生成支付字符串）
  → 返回 orderInfo 唤起客户端

支付状态查询：
flutter-mall → front-api /orderPayQuery（orderId）
  → OMS/QueryOrderDetail（获取订单状态）
  → 返回 {paid, remainingSeconds, orderStatus, closed, reason}

支付回调：
第三方支付 → front-api /notify（支付宝回调）
  → AlipayClient/DecodeNotification
  → OMS/UpdateOrder（订单状态→待发货）
  → 返回 ACK
```

### Architecture Compliance

- **通信拓扑**：`flutter-mall → front-api → [OMS + AlipaySDK] → 客户端`；遵循 REST + gRPC + 第三方 SDK 分层
- **Logic 层编排**：front-api 层负责订单校验、金额映射、支付签名编排；OMS 只做单一职责数据存取
- **错误处理**：front-api 使用 `errorx.NewDefaultError(s.Message())` 封装 gRPC 错误；Flutter 层区分网络异常、业务错误（订单已关闭/已支付）
- **Flutter 网络层**：使用 `HttpUtil.post`/`postWithHeaders` 统一调用
- **Scope 模式**：遵循 Story 5-1~5-4 已知约束，scope 在 Epic 5 结算链路统一处理
