# Story 5.5: 支付发起、结果页与恢复入口

Status: review

## Story

As a 消费者,
I want 发起支付并在支付中断时快速恢复,
So that 我可以把首单交易顺利完成而不会因为状态不明而放弃。

## Acceptance Criteria

1. **Given** 订单已成功创建且处于待支付状态 **When** 消费者选择支付方式并发起支付 **Then** 系统生成支付请求并返回当前支付结果页或待支付恢复入口 **And** 用户无需等待未来订单模块也能确认当前支付状态。

2. **Given** 支付中断、失败或结果未及时返回 **When** 消费者回到支付结果页或待支付恢复入口 **Then** 系统展示剩余支付时间、失败原因和继续支付动作 **And** 用户可以继续支付或返回结算完成页而不丢失上下文。

→ Dev agent 只需实现 `_doPay()` 内部逻辑和状态轮询。

**约束 3：OMS 订单状态模型**

`oms_order_main` 中订单状态（`status`）：
- 0 = 待支付
- 1 = 已支付（待发货）
- 2 = 已取消
- 3 = 已完成
- 4 = 售后中

`pay_status`（支付状态）：
- 0 = 未支付
- 1 = 已支付

→ `OrderPay` 需校验 `status == 0`；`OrderPayQuery` 需融合 OMS 状态和第三方查询结果。

**约束 4：OMS proto 缺少 `pay_type` 字段**

`AddOrderReq` 无 `pay_type` 和 `pay_amount` 字段。实际支付方式由支付回调写入 OMS：
- OMS `UpdateOrderReq` 可以更新 `order_status` 和 `pay_status`
- 支付金额需要通过 `QueryOrderDetail` 查询原始 `pay_amount`

→ 订单支付金额从前端传入改为从 OMS 查询：`QueryOrderDetail` → `pay_amount`（元，float32）。

**约束 5：AliPayNotify 回调幂等处理（来自 Story 5-4 债务）**

`generate_order_logic.go` 中 Saga 警告注释指向 Story 5.7（Epic 7），但本 story 只需处理 `AliPayNotify` 的幂等逻辑：

`AliPayNotify` 当前实现：无幂等处理，重复回调会重复更新 OMS 状态。修复方向：
- 同一 `outTradeNo` 重复回调：先查 `pay_status`，若已是 `1`（已支付）则直接返回 success，不再重复调用 `UpdateOrder`
- **支付成功无需库存补偿**（库存补偿是取消/超时订单 Saga 的职责，见 Story 7.4）

→ 本 story 在 Task 4.3 中实现幂等处理，不引入 saga_log 表（那是 Story 7.4 债务）。

### 正确通信拓扑

```
支付发起：
flutter-mall → front-api（POST /api/order/pay, orderId + payType）
  → OrderPayLogic: 校验 orderStatus==0 → 查询OMS pay_amount → TradeAppPay/TradeAppPayWechat
  → 返回支付唤起参数（支付宝string / 微信mweb_url）
  → Flutter 调起支付宝/微信SDK

支付回调：
支付宝/微信 → front-api（GET /api/pay/notify，无JWT）
  → AliPayNotify / WechatNotify:
      - 幂等检查：pay_status已=1则直接返回success
      - 更新OMS: status=1, pay_status=1
  → 返回success（⚠️无需库存补偿，库存补偿是取消/超时Saga职责）

支付状态查询：
flutter-mall → front-api（GET /api/order/payQuery?orderId=xxx）
  → OrderPayQueryLogic: OMS状态 → [第三方TradeQuery(可选)] → 状态融合
  → 返回 orderStatus / payStatus / expireTime（剩余秒数）
  → Flutter 轮询或跳转结果页
```

### 剩余支付时间（M4 修复）

`OrderPayQueryResp.expireTime` 为订单剩余支付秒数。OMS 订单需包含创建时间字段，后端计算：
- `expireTime = 订单创建时间 + 配置超时时间 - 当前时间`（秒）
- 前端展示倒计时；`expireTime <= 0` 时展示"已超时"

### Architecture Compliance

- **通信拓扑**：`flutter-mall → front-api → [OMS + 支付宝/微信 SDK] → MySQL`；遵循 REST + gRPC + 第三方支付分层
- **Logic 层编排**：front-api 层负责订单状态校验、金额查询、支付渠道调用、状态融合；第三方 SDK 只做唤起和回调
- **幂等保护**：支付发起（Redis key `pay:idempotent:{orderId}`，TTL=60s）和回调（outTradeNo 重复检查）
- **Saga 补偿**：支付成功 → OMS 状态更新 → 优惠券/积分已核销状态标记（库存无需释放，支付后是待发货而非取消）
- **错误处理**：front-api 返回明确错误码，Flutter 层映射为用户可理解文案
- **Scope 模式**：遵循 Story 5-1~5-4 已知约束，scope 在 Epic 5 结算链路统一处理
