# Story 5.1: 商品加购与商户归属校验

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 消费者,
I want 从商品详情把商品加入购物车,
So that 我可以开始组织本次购买清单。

## Acceptance Criteria

1. **Given** 商品详情页展示有效规格和库存 **When** 消费者选择规格与数量并点击加入购物车 **Then** 系统将对应商品加入购物车 **And** 记录当前商品、规格、价格快照（商户归属信息在商品快照中体现）。

2. **Given** 商品库存不足、规格失效或商品已下架 **When** 消费者尝试加购 **Then** 系统拒绝本次加购并说明具体原因 **And** 不产生错误购物车项。

> **⚠️ MVP 范围说明**：商户级别隔离（跨商户购物车隔离）在 Story 5.3/5.4 确认单层实现；本 story 的"商户归属"体现为商品快照中的 merchant 信息，购物车层不做跨商户强制过滤。

## Dev Notes

### 架构约束与边界（本 story 最重要的发现）

**约束 1：oms-rpc 是纯数据服务，不做跨服务 RPC 调用**

`rpc/oms/internal/svc/service_context.go` 只注入了 `gorm.DB` 和 `RabbitMQ`，没有 ProductService 客户端。OMS 的 60+ 个 logic 文件没有任何 gRPC 调用，全部依赖 GORM 直接操作数据库。

→ 因此："在 oms-rpc 的 AddCartItemLogic 中调用 PMS 查询商品状态" **无法实现**，必须将校验逻辑移到 front-api 层。

**约束 2：front-api JWT 不携带 scope，ResolveEffectiveGovernanceScope 永远返回 platform:1**

`rpc/ums/internal/logic/memberinfoservice/createtoken.go` 创建的 JWT claims 只有：
```go
claims := jwt.MapClaims{
    "memberId":   memberId,
    "memberName": name,
    "mobile":     mobile,
}
```

没有 platform_id/tenant_id/merchant_id。`api/front/internal/logic/common/governance.go` 中的 `ResolveEffectiveGovernanceScope` 在 front-api 请求中永远 fallback 到 `platform:1`。

→ 因此：传入 oms-rpc 的 scope 是默认值，购物车层的商户归属校验**无法依赖 JWT scope**。解决方案：
- MVP：本 story 不做商户隔离，商户归属体现在商品快照中
- Epic 5 结算链路：在 UMS JWT 中补充 scope claims，或在 member 域维护会员与商户的关联表

**约束 3：PMS proto SkuStockData 缺少 lock_stock，real_stock 无法直接返回**

`rpc/pms/proto/product_spu.proto` 的 `SkuStockData` 只有 `stock` 字段，没有 `lock_stock`；`QueryProductSkuDetailResp` 同样缺少 `lock_stock`。Story 4.2 中 `query_promotion_list_logic.go` 已有 TODO 注释确认此问题。

→ 因此："校验真实可用库存（stock - lock_stock）"需要先补充 PMS proto 字段，或本 story 降级为"仅校验 stock ≥ requested_quantity"。

### Architecture Compliance

- **通信拓扑**：`flutter-mall → front-api → PMS（状态查询）→ front-api → oms-rpc → MySQL`；遵循 REST + gRPC + DB 分层
- **生成代码约束**：本 story 不修改任何 `.proto` 文件；如需修改（仅在 Task 5.1 选方案 A 时），必须修改源 `.proto` 后 `protoc` 重新生成，**严禁手改** `*.pb.go`
- **Logic 层编排**：front-api 层负责跨域编排；oms-rpc 层只做数据存取，不做业务编排
- **错误处理**：front-api 使用 `errorx.NewDefaultError(s.Message())` 封装 gRPC 错误，错误码映射在 Flutter 层完成
- **Flutter 网络层**：使用 `HttpUtil.get/post` 统一调用，**禁止** Widget 创建裸 `Dio`；幂等键通过请求头传入
- **Scope 模式参考**：`api/front/internal/logic/common/governance.go` 中 `ResolveEffectiveGovernanceScope` 已知在 front-api JWT 缺失 scope，可参考但不能直接依赖
