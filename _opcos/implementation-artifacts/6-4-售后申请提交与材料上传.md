# Story 6.4: 售后申请提交与材料上传

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 消费者,
I want 提交退货退款或售后申请并上传凭证,
So that 我可以在商品或服务出现问题时获得后续处理。

## Acceptance Criteria

1. **Given** 订单处于允许申请售后的状态 **When** 消费者选择原因、填写描述并上传凭证提交申请 **Then** 系统创建售后单据并进入处理进度 **And** 售后详情可在订单上下文中持续查看。

2. **Given** 订单状态不允许售后或材料不完整 **When** 消费者尝试提交 **Then** 系统明确说明不可申请原因或缺失信息 **And** 保留已填写内容供用户继续补充。

## Dev Notes

### 架构约束与边界（继承自 Story 6-1 / 6-2 / 6-3）

**约束 1：OMS 售后数据模型**

`OrderReturnService.AddOrderReturn` 参数（来自 `order_return.proto`）：
- `order_id`：关联订单 ID
- `member_id`：会员 ID（来自 JWT）
- `type`：售后类型（0=退货退款, 1=仅退款, 2=换货）
- `reason`：退货原因（**文字字符串**，⚠️ 不能传 reasonId 数字）
- `description`：问题描述
- `proof_pic`：凭证图片（base64 字符串，逗号分隔）
- `status`：0（待审核）

**⚠️ `AddOrderReturn` 返回类型仅为 `pong`（连通性测试字段），无 ReturnId / ReturnNo**
- Story 6-4 必须在 `AddOrderReturn` 之后再调用一次 `QueryOrderReturnList(orderId, memberId, status=0)` 获取售后单 ID 和单号
- 不能假设可以从 RPC 返回值直接读取这些字段

`OrderReturnService.QueryOrderReturnDetail`（id 参数，无 memberId 归属校验）：
> ⚠️ **严禁直接用于消费者侧售后查询**。前端查询售后详情需通过后端 API 封装，后端 Logic 层做 memberId 归属校验。

**约束 2：售后申请权限边界**

- 售后单只能由订单所属会员提交
- 后端 Logic 层必须做 memberId 归属校验（先 QueryOrderDetail 确认 owner）
- 前端按钮展示条件：`status == 3 || status == 7`

**约束 3：Flutter 按钮状态（Story 6-1 / 6-2 确认）**

| OMS Status | 按钮 | 按钮说明 |
|------------|------|---------|
| 0 | 取消订单 + 立即付款 | Story 6-2 |
| 1 | （无售后按钮） | |
| 2 | 查看物流 + 确认收货 | Story 6-1 / 6-3 |
| 3 | 申请售后 | Story 6-4 |
| 5 | 无按钮 | Story 6-2 |
| 7 | 申请售后（已有售后单） | Story 6-4 |

**约束 4：Scope 模式（Epic 5 / Epic 6 已知约束）**

- `common.GetMemberId` 从 JWT 提取 memberId，消费者只能提交本人订单的售后
- OMS 层做二次归属校验

### 正确通信拓扑

```
售后原因列表：
flutter-mall → front-api（POST /api/order/queryReturnReasonList）
  → QueryReturnReasonListHandler → QueryReturnReasonListLogic
  → OrderReturnReasonService.QueryOrderReturnReasonList
  → 筛选 status==1 的原因
  → 返回 ReasonList{id, name}

售后申请提交：
flutter-mall → front-api（POST /api/order/applyAfterSales）
  → ApplyAfterSalesHandler → ApplyAfterSalesLogic
  → 归属校验（memberId from JWT）
  → OrderService.QueryOrderDetail（校验订单 owner + status 3/7）
  → 幂等：QueryOrderReturnList(orderId, memberId, status=0)
      → 已有待审核 → 返回已有 ReturnId + ReturnNo（不重复提交）
  → QueryOrderReturnReasonList（reasonId → reasonName）
  → AddOrderReturn（提交售后）
  → QueryOrderReturnList（获取新售后单 ReturnId + ReturnNo）
      → ⚠️ AddOrderReturn 返回 pong，无法直接取 ID
  → 返回 ApplyAfterSalesResp{ReturnId, ReturnNo}
```

### Architecture Compliance

- **通信拓扑**：`flutter-mall → front-api → OMS RPC`；遵循 REST + gRPC 分层
- **Logic 层编排**：front-api 负责 JWT 解析、memberId 归属校验、OMS 售后提交
- **数据隔离**：memberId 归属校验双重保护（JWT + OMS QueryOrderDetail 校验）
- **幂等设计**：通过 `order_id + member_id` 查询防止重复提交
- **Commerce State Shell**：售后申请页加载/提交中/失败/成功完整覆盖
- **Consequence Preview**：提交前明确展示售后单类型、原因和凭证数量
