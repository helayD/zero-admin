# Story 4.2: 消费者领券与优惠券资产可见

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 消费者,
I want 领取并查看符合条件的优惠券,
So that 我可以在购物前明确自己可用的优惠权益。

## Acceptance Criteria

1. **Given** 消费者进入商品详情、活动页或个人优惠券页 **When** 领取处于可领状态的优惠券 **Then** 系统将优惠券加入当前账户资产 **And** 展示已领、可用、不可用、即将过期等明确状态。

2. **Given** 优惠券不满足领取条件、已领完或已过期 **When** 消费者尝试领取 **Then** 系统返回可理解的失败原因 **And** 不会重复创建或错误占用优惠券记录。

**关键发现：**
1. **领券逻辑存在并发安全问题**：`received_count` 更新不是原子操作，高并发下可能超领
2. **已领优惠券查询有 N+1 和空指针问题**：循环内逐条查 scope，且 `First()` 无记录时 panic
3. **商品详情页已展示优惠券列表但无领取按钮**：`product_detail.dart` 的 `buildCouponList()` 已有 UI，只需增加领取交互
4. **Flutter 端缺少领券接口 URL**：`service_url.dart` 无 `addCouponUrl`，需新增
5. **proto 需要修改**：`QueryCouponData` 缺少 `receive_status` 字段，新增可领优惠券查询需要新的 proto 消息定义
6. **两套优惠券模型不一致**：`coupon_model.dart` 的 `CouponData`（有 scopeType）vs `product_detail.dart` 的 `CouponList`（无 scopeType），扩展时需注意

### Architecture Compliance

- **通信拓扑**：`flutter-mall → front-api → sms-rpc`，严格遵循 REST + gRPC 分层
- **作用域模型**：消费者端领券需要通过 `front-api` 的会员上下文获取 `memberId`，通过 `common.GetMemberId(ctx)` 从 JWT 解析
- **生成代码约束**：本 story 需要修改 `.api` 和 `.proto` 文件后重新生成；**严禁手改** `types.go`、`routes.go`、`sms.pb.go`、`sms_grpc.pb.go`
- **Logic 层编排**：领券校验逻辑全部在 sms-rpc 的 `logic` 层；front-api 只做参数透传和错误转换
- **错误处理**：front-api 使用 `errorx.NewDefaultError(s.Message())` 封装 gRPC 错误为用户可理解信息
- **Flutter 网络层**：使用 `HttpUtil.get/post` 统一调用，接口 URL 集中在 `service_url.dart`，不允许 Widget 里直接写裸 Dio 调用
- **Flutter 图片**：优惠券卡片如需展示图片，使用 `CachedImageWidget` 和 `proxyImageUrl()`
