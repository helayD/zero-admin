# Story 3.2: 个人资料与账户概览

## Status: done

## Story

As a 消费者,
I want 查看和维护个人资料,
So that 我可以让账户信息保持最新并快速确认自己的账户状态。

## FRs Implemented

- **FR9**: 会员个人资料查看与编辑（昵称、头像、签名、性别、生日）
- **FR11**: 个人中心账户概览（积分、成长值、优惠券数量、订单摘要）

## Epic Context

**Epic 3: 会员账户、地址与用户资产中心** — 消费者可以完成注册登录、维护个人资料和地址，并查看积分、成长值、优惠券及相关会员资产；运营可以管理会员规则与权益。

Story 3.1（手机号注册与登录）已完成，本 Story 在其基础上实现个人资料编辑和账户概览展示。

## Acceptance Criteria (ACs)

### AC 1: 个人中心页展示会员资料与账户概览

- **Given** 消费者已登录
- **When** 进入个人中心页面（"我的"页）
- **Then** 系统展示当前昵称、头像（或默认图标）、积分、成长值、优惠券数量、订单概览（全部订单/待付款/待发货/待收货/退款售后入口）
- **And** 数据来自 `GET /api/member/info` 接口，通过 JWT Token 中 `memberId` 自动识别当前用户

### AC 2: 个人资料编辑页 — 查看与修改

- **Given** 消费者进入个人资料编辑页（从设置→"个人资料"入口进入）
- **When** 修改昵称、头像、个性签名、性别、生日后点击保存
- **Then** 系统调用 `POST /api/member/updateMember` 提交修改
- **And** 保存成功后返回上一页，"我的"页即时刷新显示最新资料

### AC 3: 表单校验与错误处理

- **Given** 消费者提交不合法或超出限制的资料内容
- **When** 保存个人资料
- **Then** 系统给出表单级校验提示（如昵称为空、昵称超长、生日格式非法）
- **And** 不会覆盖已有有效资料，保存失败时原有数据保持不变

### AC 4: 未登录态保护

- **Given** 消费者未登录或 Token 已过期
- **When** 访问个人中心或个人资料编辑页
- **Then** 跳转至登录页（复用 Story 3.1 登录流程）
- **And** 登录成功后回到目标页面

## Dev Notes

### 架构约束

1. **认证链路**: `front-api` 使用 JWT 鉴权，`memberId` 从 JWT claims 中提取（通过 `common.GetMemberId(ctx)`），编辑接口需要传入记录的主键 `id`（非 `memberId`），两者不同
2. **API 网关**: Flutter → `front-api`(9999) → `ums-rpc`(8081)，Flutter 不直接访问 RPC
3. **生成代码禁止手改**: `api/front/internal/types/types.go`、`api/front/internal/handler/routes.go` 均为 goctl 生成，如需修改字段需从 `.api` 定义文件重新生成
4. **图片代理**: Flutter Web 外部图片必须通过 `proxyImageUrl()` 加载，不可直接使用原始 URL

### 数据库 Schema

会员信息存储在 `ums_member_info` 表，关键字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 ID（UpdateMemberInfo 使用此字段作为 WHERE 条件） |
| member_id | bigint | 会员 ID（JWT claims 中的 memberId） |
| nickname | varchar | 昵称 |
| mobile | varchar | 手机号 |
| avatar | varchar | 头像 URL |
| signature | varchar | 个性签名 |
| gender | tinyint | 0-未知，1-男，2-女 |
| birthday | date | 生日 |
| growth_point | int | 成长值 |
| points | int | 积分 |
| total_points | int | 累计积分 |
| spend_amount | decimal | 累计消费 |
| order_count | int | 订单数 |
| coupon_count | int | 优惠券数 |
| level_id | bigint | 等级 ID |
| is_enabled | tinyint | 0-禁用，1-启用 |

### API 接口规范

#### GET /api/member/info

- **认证**: 需要 Bearer Token
- **请求参数**: 无（从 JWT 提取 memberId）
- **响应体**:
```json
{
  "code": 0,
  "message": "查询会员信息",
  "data": {
    "id": 1,
    "memberId": 1001,
    "levelId": 1,
    "nickname": "用户昵称",
    "mobile": "138****0001",
    "source": 1,
    "avatar": "https://...",
    "signature": "个性签名",
    "gender": 1,
    "birthday": "1990-01-15",
    "growthPoint": 100,
    "points": 500,
    "totalPoints": 1000,
    "spendAmount": 999.99,
    "orderCount": 10,
    "couponCount": 5,
    "commentCount": 8,
    "returnCount": 1,
    "lotteryTimes": 2,
    "lastLogin": "2024-01-15 08:30:00"
  }
}
```

#### POST /api/member/updateMember

- **认证**: 需要 Bearer Token
- **请求体**:
```json
{
  "id": 1,
  "nickname": "新昵称",
  "mobile": "13800138001",
  "avatar": "https://...",
  "signature": "新签名",
  "gender": 1,
  "birthday": "1990-01-15"
}
```
- **响应体**:
```json
{
  "code": "000000",
  "message": "更新会员信息成功"
}
```

**注意**: 两个接口的 `code` 字段类型不一致 — `info` 返回 `int64(0)`，`updateMember` 返回 `string("000000")`。Flutter 端需分别处理。

### 关键风险与防护

| 风险 | 防护措施 |
|------|----------|
| `id` 与 `memberId` 混用导致更新错误记录 | `info` 接口返回的 `id` 即为 `UpdateMemberReq.Id`，不要用 `memberId` |
| 头像 URL 在 Flutter Web 下跨域 | 必须使用 `proxyImageUrl()` 包装 |
| 生日格式不匹配导致后端解析失败 | 后端固定 `2006-01-02` 格式，前端 DatePicker 产出需格式化为 `yyyy-MM-dd` |
| `updateMember` 成功后 "我的"页数据未刷新 | `ProfileEdit` 返回时需触发 `mine.dart` 重新拉取 `info` |
| 响应 code 类型不统一 | `InfoResp.code` 是 int，`MemberResp.code` 是 string，模型定义需分别处理 |
| ⚠️ `updateMember` 后端缺少归属校验 | 当前 `UpdateMemberLogic` 直接使用 `req.Id` 更新记录，未校验该 `id` 是否属于当前 JWT 用户。**前端必须只使用 `info` 接口返回的 `id`，绝不允许用户自行输入或篡改 `id` 字段**。后续应在后端补充 `memberId` 归属校验（不在本 Story 范围，但前端需做防护） |
| Token 过期导致 401 未正确处理 | `HttpUtil` 已有 401 拦截逻辑（`http_util.dart:78`），收到 401 时跳转登录页。前端无需额外处理，但需确保编辑页的网络请求走 `HttpUtil` 统一封装 |

## Previous Story Intelligence (3.1)

### 从 Story 3.1 提取的关键模式

1. **JWT Token Claims**: `{ "memberId": int64, "exp": ..., ... }`，通过 `common.GetMemberId(ctx)` 提取
2. **HttpUtil 封装**: Flutter 端使用 `HttpUtil.get()` / `HttpUtil.post()` 发起请求，Token 在 `HttpUtil` 内部从 `SharedPreferences` 读取并自动附加到 `Authorization` Header
3. **登录态存储**: Token 存储在 `SharedPreferences` 的 `token` key，登录状态通过检查 Token 是否存在判断
4. **错误响应模式**: 后端通过 `errorx.NewDefaultError(message)` 包装错误，前端收到 HTTP 非 200 或 code 非 0 时展示错误信息
5. **代码审查修复经验**: Story 3.1 审查发现需要注意的点：
   - 避免在 `types.go` 中手动修改（应通过 `.api` 文件重新生成）
   - 错误日志中不要泄露完整手机号等敏感信息
   - gRPC status error 需通过 `status.FromError(err)` 提取 message
