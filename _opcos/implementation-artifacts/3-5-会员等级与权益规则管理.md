# Story 3.5: 会员等级与权益规则管理

## Status: done

## Story

- **As a** 平台或租户运营人员
- **I want** 管理会员等级、标签、任务和消费规则
- **So that** 我可以按经营策略定义用户获得和使用权益的方式

## FRs Implemented

FR13, FR14

## Epic Context

**Epic 3: 会员账户、地址与用户资产中心**
消费者可以完成注册登录、维护个人资料和地址，并查看积分、成长值、优惠券及相关会员资产；运营可以管理会员规则与权益。

**Epic 3 Stories:**
- 3.1 手机号注册与登录 → done
- 3.2 个人资料与账户概览 → done
- 3.3 收货地址管理 → done
- 3.4 用户资产、收藏与足迹视图 → done
- **3.5 会员等级与权益规则管理 → 当前 story**

## Acceptance Criteria

### AC1: 会员运营规则配置
**Given** 运营人员进入会员运营后台
**When** 配置会员等级、标签、任务或消费规则
**Then** 系统保存规则并绑定对应作用域
**And** 前台会员权益展示和计算使用同一套规则定义

### AC2: 会员权益生效与审计
**Given** 运营调整了会员权益生效条件
**When** 规则发布成功
**Then** 变更后的权益在会员资产与后续结算链路中按作用域生效
**And** 规则调整过程留有审计记录

## Dev Notes

### Architecture Constraints

#### 技术栈
- **后端**: Go 1.22+ / go-zero v1.7+ / gRPC
- **前端**: React + Umi + Ant Design Pro + ProTable
- **数据库**: MySQL 8.0 / GORM gen (query 包)
- **ORM**: `rpc/ums/gen/model` + `rpc/ums/gen/query` (GORM gen 自动生成，**禁止手动修改**)

#### 代码生成链规则（关键！）
- `rpc/ums/gen/` 下的 `model/` 和 `query/` 是 GORM gen 生成的代码，**严禁手动编辑**
- `rpc/ums/internal/server/` 下的 server 文件是 goctl 生成的，**严禁手动编辑**
- `rpc/ums/umsclient/` 下的 client 文件是 goctl 生成的，**严禁手动编辑**
- 只允许编辑 `rpc/ums/internal/logic/` 下的 logic 文件

#### API 路由约定
- admin-api 路由前缀: `/api/ums/`
- 所有路由经过 JWT 认证 + CheckUrl 中间件
- 列表查询用 GET，创建/更新用 POST，删除用 GET（带 ids 参数）

### 审计机制说明（关键！dev agent 必读）

**`AddLogMiddleware`** (`api/admin/internal/middleware/addloglmiddleware.go`) 已在全局中间件层实现审计：
- 每个 admin-api 请求自动记录到 `sys_operate_log`（通过 `OperateLogService.AddOperateLog` RPC）
- 记录内容：操作人(userName/deptName)、请求方法、请求URL、请求参数、响应结果、浏览器/OS、耗时、治理范围(scopeType/platformId/tenantId/merchantId)
- `extra` 字段包含结构化治理信息：traceId、action、resourceType、resourceId、scopeLabel
- **当前问题**：`deriveOperateActionAndResource()` 函数只映射了 pms/oms/sms/cms 的 resourceType，**UMS 路由返回 "unknown"**
- **修复方式**：在 switch 中添加 `/api/ums/` 的 case 分支

```go
// 需要在 deriveOperateActionAndResource() 的 switch 中添加：
case strings.Contains(cleanURI, "/api/ums/level"):
    resourceType = "member_level"
case strings.Contains(cleanURI, "/api/ums/tag"):
    resourceType = "member_tag"
case strings.Contains(cleanURI, "/api/ums/task"):
    resourceType = "member_task"
case strings.Contains(cleanURI, "/api/ums/ruleSetting"):
    resourceType = "member_rule_setting"
case strings.Contains(cleanURI, "/api/ums/consumeSetting"):
    resourceType = "member_consume_setting"
```

### Anti-Patterns（严禁！）

1. **严禁在 logic 层手动添加审计日志代码** — 中间件已全局覆盖，重复添加会导致双重记录
2. **严禁手动修改 `gen/model/`、`gen/query/`、`internal/server/`、`umsclient/` 下的代码** — 这些是自动生成的
3. **严禁在 handler 或 routes.go 中手动添加路由** — 使用 goctl 生成
4. **严禁为 UMS 表添加 tenant_id/scope 字段** — 当前为单租户模式，作用域治理通过中间件 context 传递

### Key Risks & Gaps

1. **UMS resourceType 未映射（高优先级）**: `deriveOperateActionAndResource()` 缺少 `/api/ums/` 的映射，导致 UMS 操作的审计日志 resourceType 为 "unknown"。只需添加 5 行 case 分支即可修复。
2. **RuleSetting 删除接口不一致**: MemberRuleSetting 的删除是单条（`?id=`），而其他模块是批量（`?ids=`），web-admin 页面的删除逻辑也不同。（可延后统一）
3. **MemberLevel 状态更新接口参数不一致**: 使用 `isEnabled` 而非 `status`，与其他模块风格不同。（不影响功能，可延后）
4. **privileges JSON 编辑体验差**: 当前 web-admin 的 privileges 字段是 hideInTable 的纯文本。（超出本 Story AC 范围，建议延后）
