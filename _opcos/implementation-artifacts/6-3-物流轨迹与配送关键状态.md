# Story 6.3: 物流轨迹与配送关键状态

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 消费者,
I want 查看物流轨迹和关键配送状态,
So that 我可以判断订单什么时候会送达以及是否需要介入处理。

## Acceptance Criteria

1. **Given** 订单已进入发货流程 **When** 消费者打开订单详情或物流页 **Then** 系统展示当前物流状态、关键时间点和最近配送节点 **And** 配送状态与订单时间线使用一致的状态语义。

2. **Given** 物流信息暂未返回或外部依赖异常 **When** 消费者查看物流轨迹 **Then** 系统给出明确的等待或异常提示 **And** 不展示误导性的默认轨迹数据。

## Dev Notes

### 架构约束与边界（继承自 Story 6-1 + Story 6-2）

**约束 1：OMS 物流数据现状**

`OrderService.QueryOrderDetail` 返回的 `DeliveryData` 字段：
- `DeliveryData.delivery_company`：物流公司名称（字符串）
- `DeliveryData.delivery_no`：物流单号（字符串）
- `DeliveryData.receiver_address`：收货地址（用于物流摘要卡片）

> ⚠️ `OrderDeliveryService.QueryOrderDeliveryDetail` 仅用自增 id 查询，**无 memberId 归属**，严禁用于消费者侧物流查询。

| 场景 | 预期展示 |
|------|---------|
| OMS 无物流数据（未发货/物流未填写） | "暂无物流信息，包裹正在准备中" |
| OMS 有物流数据但无轨迹 | "包裹已发出，等待揽收" |
| 后续接入第三方轨迹（Story 8-6） | 展示完整快递轨迹时间线 |

### 正确通信拓扑

```
物流查询：
flutter-mall → front-api（GET /api/order/queryLogistics?orderId=xxx）
  → QueryLogisticsHandler → QueryLogisticsLogic
  → 归属校验（memberId from JWT）
  → OrderService.QueryOrderDetail（orderId + memberId 归属，含 DeliveryData）
  → 提取 DeliveryData（deliveryCompany + deliveryNo）构造 logisticsNodes
  → 若无物流数据：currentStatus = "暂无物流信息，包裹正在准备中"
  → 若有物流数据：currentStatus = "包裹已发出，等待揽收" + logisticsNodes=[发货节点]
  → 返回 QueryLogisticsResp{Code:0, LogisticsData: {...}}
```

> ⚠️ **禁止使用 `OrderDeliveryService.QueryOrderDeliveryDetail`**：该 RPC 仅用自增 id 查询，无 memberId 归属校验，不适合消费者侧物流查询。必须复用 `OrderService.QueryOrderDetail` 的 DeliveryData。
